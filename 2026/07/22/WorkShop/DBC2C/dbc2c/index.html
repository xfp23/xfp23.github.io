DBC2C - 汽车电子CAN协议工具

DBC2C —— 让 CAN 协议开发回归工程本身

软件更新地址

许可证获取地址

联系作者

DBC2C 是一款面向汽车电子、工业控制及嵌入式开发的 CAN 协议工程工具。

它以 Excel 作为协议设计入口，实现 Excel、DBC 文件与 C 代码之间的自动转换，帮助工程师摆脱重复性的协议维护工作，提升 CAN 通信开发的效率与可靠性。

1. 软件简介

1.1 功能特点

  • ✅ Excel ↔ DBC 双向转换
  • ✅ DBC 文件解析
  • ✅ 自动生成 CAN 信号描述代码
  • ✅ 自动生成 MicroCAN 协议解析库
  • ✅ 支持 Intel / Motorola 字节序
  • ✅ 支持报文与信号合法性检查
  • ✅ 支持报文名称、ID 快速搜索
  • ✅ 支持中英文界面切换

1.2 设计理念

DBC2C 采用”描述与运行分离”的设计理念。

工具本身只负责：

  • 协议文件解析
  • 数据描述生成
  • C 代码生成

而运行时的报文解包/打包则交由独立的 MicroCAN 库完成。

这样设计可以避免协议描述逻辑与业务代码强耦合，使生成的代码更容易维护和移植。

2. 项目背景

2.1 从人工解析到自动化工具

在汽车 ECU 开发过程中，CAN 通信协议通常需要同时维护 Excel 矩阵、DBC 文件以及 ECU 端解析代码。传统开发方式往往依赖人工完成信号定义维护、DBC 文件编辑、C 代码编写和位域解析，这种方式不仅效率较低，还容易因人为疏漏导致协议不一致。

DBC2C 正是源于这些实际项目中反复出现的问题。

刚进入汽车电子行业时，我曾通过编写宏定义来简化 CAN 报文的位域解析，这也是本项目最早的雏形。

后来在负责一个 BMS 热管理项目的 ECU 开发时，面对数量庞大的 CAN 信号，纯手动维护的方式已经无法满足工程需求，于是我开发了第一个基于 WPF 的自动代码生成工具：读取客户提供的 Excel 矩阵定义，自动生成对应的 C 代码。

但随着项目复杂度提高，传统的 union 位域方式逐渐暴露出问题：不同编译器对位域布局的处理存在差异，Motorola（大端）格式的信号解析十分困难，生成代码的可移植性也不足。

此外，在一次 DBC 文件维护过程中，由于 CAN 工具异常退出，大量编辑内容瞬间丢失，这件事让我意识到，整个 CAN 工具链中其实还有大量工作可以被自动化取代。

DBC2C 项目由此正式诞生。

DBC2C 的整体数据流程如下：

工具负责生成协议描述层（DBC / C 描述代码），运行时的实际打包与解包交给 MicroCAN 库完成，二者相互独立、职责清晰。

4. 核心功能

4.1 DBC 解析

DBC2C 自主实现了 DBC 文件解析模块，无需依赖任何大型第三方 DBC 解析框架。

主要功能包括：

  • 解析 CAN Message
  • 解析 Signal 定义
  • 检查信号位域
  • 检查 DLC 合法性
  • 生成 C 描述代码

解析完成后，软件会生成用于描述 CAN 协议结构的 C 文件。

同时，DBC2C 也支持由 DBC 反向生成 Excel 文件，方便测试、文档等相关人员查看协议内容。该功能依赖开源库 libxlsxwriter。

4.2 Excel 解析

Excel 是 DBC2C 推荐的协议设计入口，解析功能主要依赖开源库 OpenXLSX。

解析流程：

  1. 检查 Sheet1 第一列是否为 Message Name；
  2. 根据表头名称自动识别各字段；
  3. 根据字段信息生成对应的 DBC 数据。

列的先后顺序不会影响解析结果，只要列名符合规范即可。

对于 Resolution、Offset、Sender、Receiver 等部分非必填字段，软件会根据已有信息自动补充合理的默认值。

4.3 C 代码生成

DBC2C 支持 DBC → C 代码，也支持 Excel → DBC → C 代码，但不会直接实现 Excel → C 代码。

之所以这样设计，是因为 DBC 作为标准的协议描述格式，可以充当统一的数据中间层，让各个模块的职责更加清晰，避免功能相互侵入。

生成的文件会以 DBC 文件名命名，例如：

  • xxx_dbc2c_can_desc.c
  • xxx_dbc2c_can_desc.h

可直接集成到 ECU 工程中使用。

5. 使用指南

5.1 软件激活

由于本软件属于汽车电子功能安全相关工具的一部分，为防止软件被滥用，授权许可将不定期开放获取，并非永久免费。

获取许可证文件后，将其放置在安装目录下、与 DBC2C.exe 同一路径中，重启软件即可完成激活。

5.2 软件预览

软件支持：

  • 中英文界面切换
  • License 状态查看

8. 软件状态指示

软件左下角提供状态指示灯：

  • 红色：软件出现异常，例如激活失败、文件解析失败、程序错误等；
  • 橙黄色：软件正在执行任务，例如 DBC 解析、文件生成等；
  • 绿色：软件空闲，或任务已完成。

9. 搜索功能

9.1 按名称搜索

支持报文名称模糊搜索。例如输入 TMS，可以匹配 TMS_STA1、TMS_Sta2、TMS_sta3 三条报文。

9.2 按 ID 搜索

支持按 CAN ID 搜索，采用全字符匹配。输入十六进制 ID 即可，无需添加 0x 前缀，例如直接输入 18FFxxxx。

搜索完成后，点击 x 清除 即可恢复到搜索前的页面。
